[2026-08-07] [user] Verification harness switched from hand-rolled Node scripts to Vitest. Old plan: scripts/check-lib.ts + scripts/check-setup.ts run via `node --experimental-strip-types`, chosen for zero dependencies. Hidden cost that killed it: plain Node cannot resolve the `@/` alias, so EVERY lib/ module was forced to import siblings by relative path with explicit .ts extensions, plus allowImportingTsExtensions in two tsconfigs — production import style bent to suit a test harness. Vitest resolves `@/` via tsconfig paths, so that constraint is retired entirely; also gains per-test isolation (one failing assertion no longer aborts the run), failure diffs, and watch mode. check:setup ALSO goes through Vitest rather than staying a plain script — otherwise the `@/` restriction survives in lib/db/ and lib/storage/ and the whole trade buys nothing. Kept as separate globs: `check:lib` = `vitest run lib` (no credentials, ever), `check:setup` = `vitest run scripts` (needs .env.local, Phase 4). Tests colocated as lib/*.test.ts. Hard rule 8 reworded.
