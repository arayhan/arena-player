Design System

Light, clean, blue-and-white — deliberately the inverse of the dark benchmark. Every value below comes from docs/DESIGN.md, which is the source of truth. This page renders the system; it does not define it.

Reference artifact, not production code.

Fonts load from a CDN here because this file has no build step — production uses next/font/google for self-hosting and zero layout shift. Motion here is plain CSS; production routes all animation through lib/motion.ts. Copying either pattern into the app breaks hard rules 6 and 7.

Core component

Slot cell

One column, full-width rows. Chosen for one concrete reason: “Menunggu Konfirmasi” is 20 characters. A 3-column grid at 375px gives ~110px per cell and the label cannot fit at all; 2-column forces truncation. Full-width fits it at full size and yields a tap target well above 44px. Click an available slot to see the selected state.

Past slots render identically to booked — not a shortcut. GET /api/availability returns booked for today’s elapsed slots, so the client genuinely cannot tell them apart. Distinguishing them would need an API change first. Disabled cells stay visible, never hidden: a user needs to see that 18.00 is taken, not wonder why the list skips it.

Core component

Date pills

Fully rounded so the row reads as horizontally scrollable without a hint — the one place the pill radius is used. overscroll-behavior-x: contain stops a swipe bouncing the page. Click to select; scroll the row sideways.
