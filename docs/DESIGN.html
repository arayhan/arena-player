01

Name each part for its job

+ 20 names

The semantic layer. A part stops being navy-900 and becomes “the foreground”. Re-theming edits this layer and nothing else.

Semantic tokenPartJob
--color-pageblue-50Instruction-page ground
--color-bgwhiteThe plates content sits on
--color-fgnavy-900Body, headings, keylines
--color-fg-mutednavy-400Secondary text
--color-interactiveblue-600Links, focus, available slots
--color-bordergrey-200Hairlines
--color-focusblue-600Focus ring — restyled, never removed

Why --color-fg-muted is not a grey. This page's ground is blue-50, and grey-500 computes to 4.44:1 there — under AA. A hue-tinted mute clears both grounds: 6.38:1 on blue, 6.94:1 on white. On a coloured surface, tint the secondary text from that hue rather than reaching for grey.

02

Assign the named parts to components

+ 40 assignments

The step that usually gets skipped. Every component rule on this page reads from a --slot-*, --pill-*, --button-* or --input-* token — never from a raw part.

--navy-900 → --color-accent-strong → --button-primary-bg

Three hops, one direction. A component that reaches straight to var(--navy-900) looks identical today and breaks the moment the theme moves — and it breaks silently, which is why the indirection is worth its extra token. Developers copy code, not prose, so this page is the reference Phase 2 inherits.

04

The slot cell

+ 6 states

One column, full-width rows, for one measurable reason: “Menunggu Konfirmasi” is 20 characters. A 3-column grid at 375px gives ~110px per cell and the label cannot fit; 2-column truncates it. Full-width fits it at 146px inside a 343px row. Click an available slot, then click it again to deselect.

Selection lives in aria-pressed, not in a class. A class-only selection looks correct and is silent to a screen reader, and this is the pattern Phase 2 copies into the product's core interaction. Unavailable cells stay visible and focusable via aria-disabled, never native disabled — a user needs to see that 18.00 is taken.

Elapsed hours are not booked hours. GET /api/availability returns booked for today's past slots, but the client already knows the time and the canonical starts, so it derives “elapsed” itself — no API change, contract stays firm. Step “Finished model” shows the treatment: one collapsed “Sudah lewat (N)” row instead of nine “Terisi” labels that make the day read as sold out.

So elapsed is a fourth state, not a shade of booked. It was rendering in the danger triple while carrying the label “Sudah lewat” — which contradicts the paragraph directly above and overstates how busy the day was. It is now neutral and recessed — the neutral family rather than the danger one, so it reads as “gone” instead of as “taken”. Both are unavailable, but only one of them is somebody else's booking, and the label carries that distinction non-visually so nothing here depends on colour alone.

It is also the only cell with no visible border, because its border matches its fill. That is deliberate: every other state announces itself with a fill — amber, red, blue — and elapsed shipped with grey-50, which measured 1.05:1 against an available cell's white. No surface difference at all, leaving border hue as the only non-text signal, which is what step 07's own rule forbids. grey-200 is the value the disabled button already uses, so the fix reaches for existing vocabulary rather than a new token — and borderlessness is a structural difference rather than an accent stripe.

06

Buttons & inputs

+ 3 controls

48px tall throughout, comfortably above the 44px tap minimum. Tab through this plate to check every focus state.

Nomor tidak valid. Gunakan format 08xx atau 62xx.

The error state does not depend on its border alone. A border carrying a state by itself must clear 3:1 (WCAG 1.4.11). red-300 on a white field is 1.90:1 and fails, so the boundary is red-800 at 8.31:1 and the field fills red-100 — two signals, neither hue-only. Errors tie to their field via aria-describedby; focus rings are never removed.

08

Waiting, empty, and failed

+ 4 states

The four states with no happy-path screen. Every one of them is reachable on a mid-range Android in an in-app browser, so none of them is an edge case — and a grid with no story for “the request failed” renders as a day that looks fully booked.

Skeleton rows at the real 56px height, so nothing shifts when data lands.

Submitting

The button names what is happening and stops accepting a second press.

aria-disabled here, not native disabled: the control keeps its place in the tab order so focus does not jump while the request is in flight.
